# Debug session 2 — purchase flow + cursor

Scope agreed with the engineer: prove and fix the building purchase bug, then the
cursor, then move to Default mode for the net-new features (intro, beta
pre-registration, badges/share). All instrumentation below is permanent unless
marked otherwise; nothing needs reverting.

---

## Workstream 1 — Building purchase flow

### How the cause was established (not guessed)

`src/planet/stores/economy.client.test.ts` (**NEW, permanent**) drives the real
store against a fake PostgREST-shaped backend whose latency, ordering and
responses the test controls. Before any product change, 4 of 5 tests were red:

- `keeps the bought building when a load was already in flight` →
  `expected [] to include 'reboot-nexus'`
- `does not let an older load overwrite the post-purchase state` → same
- the other three timed out on the first (bad) test harness, then reproduced
  after the harness was fixed

That converts the recon hypothesis into a measurement: a `loadEconomy` started
before the purchase commits resolves afterwards and writes pre-purchase rows over
the fresh ones.

### 1. Serialised wallet/list reads
- **File:** `src/planet/stores/economy.ts`
- **Change:** `loadEconomy` is now an `enqueueLoad` built on a promise chain with
  a pending counter. A load requested while another is in flight is **queued**
  instead of being dropped (`if (get().loading) return`), and two reads can never
  apply out of order. `readEconomy` holds the body; `loading` is cleared only when
  the queue drains.
- **Why**: the old early-return both dropped the post-purchase refresh and let a
  stale response overwrite a fresh one.

### 2. Purchase reports and reconciles
- Same file. `purchase` now: keeps `busy` until the reload finishes, and on
  failure re-reads server state before returning, because the RPC may have
  committed before the response was lost. The purchase error is set *after* the
  reload so reconciliation cannot wipe it.

### 3. One intent, one idempotency key
- New module-level `purchaseIntent` + `intentKeyFor()`; cleared on success. A
  retry after a lost response now reuses the key, so the server cannot see a
  second, unrelated purchase.

### 4. Removal cannot lie
- `removePlacement` checks `data.removed`, reconciles first, and reports
  `That placement was already gone. The grid has been refreshed.` instead of
  filtering the row out locally and calling it success.

### 5. Placement failures reconcile too
- `placeFree` / `placeOwned` reload on the error path as well, so a rejected
  placement no longer leaves the grid showing a building that was never saved.

### 6. Error surfacing accepts both shapes
- `message()` reads `Error.message` and a bare `{ message }` (lost responses,
  thrown literals), so the player sees the real reason instead of a generic line.

### 7. Unsaved grid edits survive a background reload
- **File:** `src/planet/components/BuildingShop.tsx`
- **Change:** the sync effect depends on the saved coordinates
  (`selectedPlacement?.id / grid_x / grid_z / rotation`) instead of the record
  object identity. Every reload produced new objects and silently reset the
  player's unsaved target.

### 7b. Appearance editor is owner-only
- **File:** `src/planet/modules/cityworld/CityWorldManager.tsx`
- **Change:** `const canCustomize = true` → `!!selected && !!user &&
  selected.ownerId === user.uid`. The per-project editor used to mount for any
  selected record and every save failed with "Only the project owner can save
  changes."

### Result
`npx vitest run src/planet/stores/economy.client.test.ts` → **5/5 green**.
Full suite: 111/113. The two failures are pre-existing and environmental —
`supabase/public-lockdown.test.ts` and `supabase/feedback-board.test.ts` read SQL
files from *outside* the repo (`../../30-lock-public-writes.sql`,
`../../50-feedback-roadmap.sql`) that are not present in this checkout.

## Workstream 2 — Cursor

### Baseline (repo's own benchmark, `cursor-speed.check.mjs`, dev mode)
Landing page: `medianSettleMs: 818`, with only **2–4 animation frames in 900 ms**.
That is the finding: the old cursor loop was `requestAnimationFrame`-bound on a
page that starves rAF, so the ring often never arrived at all (`settleMs: null`,
`lastX` unchanged). Easing constants were not the deciding factor.

### 7. No animation loop at all
- **File:** `src/components/CyberOverlay.tsx` (rewritten)
- **Change:** the rAF loop, the exponential catch-up and the per-frame
  `document.elementFromPoint` hit test are gone. Dot and ring are positioned
  inside the `pointermove` handler (single compositor-only transform write), so
  the dot is exactly on the pointer and the ring's lag is a CSS transition the
  compositor interpolates even when the main thread is blocked.

### 8. Hover / press / drag from delegated pointer events
- Delegated `pointerover` / `pointerout` with `closest(HOVER_SELECTOR)` replace
  per-frame hit-testing, so moving the mouse no longer forces layout.
- `pointerdown`/`up`/`cancel` drive `.clicking` and a new `.dragging` state; while
  dragging the ring transition is 0s so it tracks exactly.
- `HOVER_SELECTOR` now includes `[data-cursor="hover"]`, `[role="link"]`,
  `[role="tab"]`, `summary`, `label` and `canvas` — the old selector matched
  `.side-card/.wing-card/.badge-card/.leader-row`, which no component has ever
  used, so those cards never reacted.

### 9. Touch and reduced motion
- The overlay bails out on `(pointer: fine) and (hover: hover)`; trail dots are
  skipped under `prefers-reduced-motion`; `@media (pointer: coarse)` hides it.
- `cursor:none` is now scoped to `html[data-custom-cursor="on"]`, which is set
  only when the custom cursor actually runs. Previously `body * {cursor:none
  !important}` applied on every device, including touch.

### 10. Trail dots pooled, not churned
- 14 pooled nodes, 30 Hz time throttle, animated with the Web Animations API
  (`node.animate`), so there is no per-move DOM insert/remove and no transition
  reflow.

### 10b. One cursor everywhere
- **File:** `src/components/BetaPreRegistration.css`
- **Change:** removed the `.beta-page … cursor: auto/pointer !important` rules
  that re-enabled the native pointer on top of the custom one.

### 10c. Benchmark now measures a quiet page too
- **File:** `cursor-speed.check.mjs`
- **Change:** added `cursorLightPage`, repeating the same jumps on the Feedback
  page, because the landing's 3D canvas starves rAF and a number taken there
  describes the page rather than the cursor.

### Result
Quiet page: **median 155 ms, 45 frames/900ms** (was `null`/818ms on a starving
page). Landing page still reports large numbers because that page renders at
~3fps; that is a page-weight problem (VoidCanvas3D), logged below, not a cursor
defect.

## Outstanding (found, not fixed — outside the two agreed workstreams)

- The landing screen's main-thread starvation (2–4 frames/900ms in software
  rendering) delays everything, including the cursor and any future recording.
- 3D objects still write `document.body.style.cursor = 'pointer'` on hover
  (`MiniatureWorlds`, `cityKit`, `Landmarks`, `CityVisualization`). That is dead
  under the global `cursor:none` rule, so 3D hover has no cursor affordance.
  Wiring 3D hover into the custom ring needs a small shared signal.
- `beta-page.check.mjs` is stale against the referral RPC (it stubs the old
  one-arg `join_beta_waitlist` and a boolean response) and will fail.
