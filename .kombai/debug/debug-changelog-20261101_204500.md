# Debug session — "three black districts" (Health, Education, Community)

## Findings

1. **Not a scene defect.** All three districts render. Health was observed rendering
   correctly (tidal pavilions, garden tree, shafts, mist) after a long wait on a page
   whose canvas had previously sampled pure black.
2. **Framebuffer evidence.** Polling the live canvas (`preserveDrawingBuffer: true`) at
   1.5 s intervals: pure black (`mean 0`, alpha 255) for the first ~11 s after
   navigation, then content. The renderer was clearing to opaque black with nothing
   submitted.
3. **Why the manager shows black with a full HUD.** `readyKey` is set by `Ready`, which
   only counts three rendered frames. It does not prove the district has mounted or
   produced a visible frame. When the lazy city chunk and its shaders are still
   compiling, the manager already reports ready, hides the loading affordances, and the
   user sees an unexplained black canvas.
4. **Why my captures were black.** The capture rig used fixed sleeps (8–11 s) instead of
   waiting for a readiness signal, so it screenshotted inside that compile window.
   Districts already compiled by Vite (Graveyard, Legend, Robotics, Space) survived it.

## Outstanding (not fixed)

- `readyKey` must be gated on the district actually mounting and producing a visible
  frame — e.g. a `SceneReady` sentinel rendered *inside* the district subtree that
  reports after the first non-empty frame, or a one-frame `gl.readPixels` probe on the
  canvas in `Ready`. Until then the manager can declare ready while the canvas is empty.
- Capture rig must follow the same readiness signal. The working probe is the
  `drawImage(canvas) → 2D context → mean luminance` check used above.
